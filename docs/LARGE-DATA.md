# 대량 기록의 화면 표시 검증

1.1.1 정식 배포 전 2026-11-13에 합성 데이터로 검증했습니다. 실제 계정에 기록이 적더라도 저장된 상태와 같은 형식을 만들어 공통 UI를 테스트할 수 있습니다. 실제 ID·닉네임·채팅·인증 정보는 사용하지 않았습니다.

## 재현한 문제와 보완

수정 전에는 긴 닉네임과 큰 숫자가 1920px 화면에서 문서 폭을 3473px까지 늘리는 실패를 확인했습니다. 그리드의 최소 폭, 카드·숫자 줄바꿈, 좁은 화면 내비게이션, 표의 내부 스크롤을 보완했습니다. 문서 전체의 가로 스크롤을 숨겨 가리는 방식은 사용하지 않습니다.

많은 항목을 한 번에 DOM에 넣던 팔로우·구독·방송 표는 페이지로 나누었습니다. 페이지를 바꿔도 저장 자료를 삭제하거나 합계를 줄이지 않습니다. 팔로우 검색과 페이지 이동도 테스트합니다.

시청자 집계를 한 번의 화면 갱신에서 반복 계산하지 않도록 재사용하고, 각 시상 기준은 전체 시청자를 정렬하는 대신 상위 10명만 유지합니다. 동점의 닉네임 정렬과 기존 순위가 같다는 회귀 테스트를 포함합니다.

## 검증 자료와 결과

| 항목 | 합성 자료 |
|---|---:|
| 개인 채팅 | 100,000건 |
| 스트리머 FULL 원문 | 한 시청자의 100,000건 |
| 스트리머 시청자 | 50,000명 |
| 팔로우 채널 | 10,000개 |
| 방송 이력 | 3,000건 |
| 문자열 | 수백 자의 공백 없는 이름, 10,000자 원문 |
| 수치 | 조 단위 채팅 수와 15자리 포인트 |
| HTML 내보내기 화면 | 시청자 5,000명, 닉네임·후원 포함 |

Windows의 Playwright Chromium에서 공통 화면을 로컬 테스트 서버로 열었습니다. API·외부 요청은 차단하고 상태 조회만 합성 응답으로 대체했습니다. `npm run test:large-ui`로 재현합니다.

- 화면 폭 1920 / 1024 / 768 / 390px에서 홈·채팅·채널·스트리머·안내 화면을 검사했습니다. 시상식까지 총 21개 측정에서 문서와 숫자 카드의 가로 넘침이 없었습니다.
- 긴 원문 모달은 1024/390px에서 검사했고, 본문은 내부 세로 스크롤로 제한됩니다.
- 개인 채팅 40행, 시청자 목록·방송 표 50행, 팔로우 60개 이하의 화면 요소만 만들고 다음 페이지와 검색 결과를 확인했습니다.
- 원문 상세는 최신 200개까지 표시하면서 전체 100,000건 개수를 유지했습니다.
- HTML 출력은 390px에서도 문서가 넘치지 않고 표 안에서 가로 스크롤됩니다.
- 렌더러 오류 0. 실제 EXE 화면 및 MV3 확장 통합 테스트도 별도로 실행합니다.

## 보장하지 않는 것

이 검사는 **화면 표시와 목록 처리** 검증입니다. 데이터를 메모리에 만들어 넣으므로 JSON/IndexedDB의 대규모 읽기·쓰기, Electron 프로세스 간 전체 상태 복사, 실계정 수집 속도, 저장 공간 부족, 수백만 건의 장시간 운영 성능을 검증하는 부하 시험은 아닙니다.

현재 저장소는 전체 스냅샷을 처리합니다. FULL 원문이 커지면 로딩·저장·검색·JSON/HTML 내보내기에 시간이 걸리거나 메모리가 부족할 수 있습니다. 페이지 분할은 화면 요소의 수를 제한하며, 메모리에 적재하는 데이터 전체를 제한하지 않습니다. 수백만 건 이상을 다루려면 메시지별 저장과 필요한 부분만 읽는 구조가 다음 개선 과제입니다.

EXE와 확장은 같은 화면 코드를 쓰지만 일반 Edge 실설치와 모든 OS 배율·브라우저 확대 조합을 검사한 것은 아닙니다. 실제 앱·브라우저와 하드웨어에 따라 결과는 달라집니다.
