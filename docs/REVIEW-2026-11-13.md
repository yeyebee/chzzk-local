# 2026-11-13 전체 검토와 수정 내역

검토 기준은 공개 버전 1.1.0(`b371d59`), 수정 내용은 1.1.1에 반영했습니다. Windows EXE와 Chrome/Edge 확장이 공유하는 수집·분석·저장·화면, 플랫폼별 인증·내보내기·빌드를 함께 확인했습니다. 사용자 실계정 프로필과 실행 중인 수집은 테스트에 사용하지 않았습니다.

## 우선 수정한 문제

P1은 기록 손실·잘못된 결과·수집 불능으로 이어질 수 있는 문제, P2는 특정 조건에서 누락·오해·불편을 만드는 문제입니다. 보안 취약점 등급을 뜻하지 않습니다.

|---|---|---|---|
| P1 | 이전 달 후원을 조회한 뒤 다른 기간으로 바꾸거나 최신 조회가 실패하면 오래된 금액이 현재 순위·방송 외 후원에 섞임 | 자료의 성공 상태와 기간 포함 관계를 확인하고 KST 날짜로 필터. 실패 자료는 보존하되 현재 집계에서 제외 | `packages/core/analysis.mjs` |

취소된 후원만 있는 정상 응답은 오류가 아닌 빈 결과로 교체합니다. 이전 채팅 페이지도 중복 제거 후 집계합니다. 사용하지 않는 화면의 무거운 재계산을 줄였고, 내보내기 파일 선택 중 계정이 바뀌어도 처음 선택한 계정 자료를 사용하도록 했습니다. 확장 빌드는 확인한 출력 디렉터리를 비운 뒤 구성하여 이전 빌드의 삭제된 파일이 남지 않도록 했습니다.

## 검증

- 단위·수집 회귀 테스트 42개 통과: 기존 24개에 이번 검토의 18개 추가. 최초 작성한 회귀 테스트 8개는 수정 전 실패를 확인했습니다.
- 오류 주입: 저장 실패와 지연 저장, 실패한 스냅샷, 금액 스키마 변경, 잘못된 기록 구조. 수집 잠금 해제·저장 완료 순서·기존 자료 보존을 확인했습니다.
- 합성 API로 과거 기간 탐색, 완료 후 새 메시지 추가, 갱신 도중 중단·재개, 동일 익명 후원과 서버 ID 중복을 확인했습니다.
- Electron 개발 UI: 격리된 임시 프로필, 렌더러 오류 0, sandbox/contextIsolation 활성·Node 비활성.
- 실제 MV3 패키지를 별도 Chromium 프로필에 로드한 통합 테스트: 합성 응답 수집, FULL 보관, 차단, IndexedDB 재시작, 중복 대시보드 잠금. 원문 삭제 뒤 탭 이동·새로고침에서도 원문이 없고 집계와 FULL 설정이 유지되는지 확인했습니다.
- `npm audit`: 개발 도구 포함 알려진 취약점 0건(검사 당시). 이 결과가 코드 전체의 안전성을 보증하지는 않습니다.

정식 배포 전 [대량 기록 표시 검증](LARGE-DATA.md)을 추가했습니다. 긴 이름과 큰 숫자의 가로 넘침을 재현해 수정하고, 팔로우·구독·방송 표를 페이지로 분할했습니다.

## 남은 검증과 구조적 한계

1. **실제 스트리머 계정의 성공 여부**: 실제 소유자 인증으로 방송·후원·선물·성별·상세 채팅·차단 전 구간을 검증하지 않았습니다. 합성 API 테스트는 권한·서비스 응답이 실제로 같다는 보증이 아닙니다. 실패한 단계와 이유를 앱에서 확인할 수 있습니다.
2. **대용량 FULL 성능**: JSON/IndexedDB 스냅샷과 화면으로 전달하는 상태가 전체 기록을 포함합니다. 숨긴 화면의 재계산은 줄였지만 수백만 메시지를 대상으로 한 속도·메모리 검증은 하지 않았습니다. 장기적인 개선은 메시지별 저장과 페이지 단위 읽기입니다.
3. **기간이 다른 지표**: 스튜디오 채팅·제한 횟수는 서버 누적값, 구독자·팔로워는 조회 시점, 상세 메시지 유형은 수집된 과거 기록 전체입니다. 날짜 필터로 모든 지표를 동일 기간으로 자를 수 없습니다. 조회 시점 이후 제재 변경도 실시간 반영하지 않습니다.
4. **자료의 완전성**: 상한·권한·서비스 보관기간·삭제/비공개 여부에 제한됩니다. 완료한 다시보기의 과거 삭제나 편집을 자동 동기화하지 않습니다. 선택한 원문 모드를 바꿔도 과거 원문이 자동 복원되지는 않습니다.
5. **이벤트 식별자 없는 목록**: ID가 없는 동일 시각·금액의 두 후원을 임의로 하나로 합치지 않습니다. 수집 도중 서버 목록이 바뀌어 발생한 겹침까지 완벽히 판별할 수는 없습니다.
6. **운영·배포**: Windows x64와 Playwright Chromium에서 확인했습니다. Edge 실설치·대규모 장시간 실행·OS 강제 종료 복구는 별도 검증이 필요합니다. EXE 코드 서명, 자동 업데이트, JSON 가져오기·저장소 동기화·앱 자체 암호화는 미지원입니다.
7. **CI**: 현재 GitHub 인증에는 workflow 쓰기 권한이 없어 자동 실행 워크플로는 설치하지 않았습니다. `docs/ci-example.yml`을 제공하고 이번 검증은 로컬에서 실행했습니다.

## 확인 방법

1. 기간을 바꾸고 후원 수집을 끄면 과거 금액이 현재 금액으로 표시되지 않는지 봅니다. 수집 결과에서 자료의 기간·상태를 함께 확인합니다.
2. FULL로 소량 수집 후 **보관한 원문만 삭제**를 누르고 새로고침합니다. 원문은 없고 통계는 유지됩니다. 이후 새 원문 보관을 원하지 않으면 수집 설정을 MIN으로 바꿉니다.
3. 상세 메시지 수집 완료 후 다시 실행하면 새 메시지를 찾습니다. 조회 한도에 걸리면 다음 실행에서 이어가며 상세 창에 갱신 시각·진행 상태가 보입니다.

계산과 보관 정책은 [기능과 계산 범위](FEATURES.md), [데이터 흐름과 보관](PRIVACY.md)에 설명되어 있습니다.
